# 南京麻将牌桌体验优化 001

状态：已完成本地实现和浏览器模拟验证，等待 owner review；未发布，真实手机验收待做。

## 牌墙素材和区域

- `client/public/mahjong/walls/top.svg`：上下牌墙单张俯视牌背，包含绿色牌面、白色牌体和厚度。
- `client/public/mahjong/walls/side.svg`：左右牌墙单张侧向牌背，采用独立比例和轮廓。
- `MahjongWallStack.vue` 根据座位方向选择素材，按服务端每墩 `0/1/2` 张画出零、一、两层；空墩保留位置，不补画牌。素材通过 `object-fit: contain` 保持比例，不进入可打牌的牌码清单。既有素材生成脚本只写入牌面、雪碧图及预览文件，不删除 `walls/`。
- 头像靠外，手牌、副露、花牌在对应桌边的独立区域，四家弃牌保持中央分区；本家花牌位于手牌前侧，副露在手牌右侧。常驻信息仅保留剩余牌、翻倍、玩家及行动倒计时；房号位于菜单。

## 结算和操作

- 左侧按牌色与点数整理胡家手牌，用服务端 `winTile` 标记胡牌张；下方显示碰杠、花杠和散花。右侧把服务端已有分项分为牌型、硬花、软花和天胡/地胡/花开/杠开加成，保留零值和合计，未改变计分规则。页脚按实际 `paid` 计算各家本手净收付，逐笔流水单独打开。多人胡通过切换选择胡家；流局使用独立状态。
- 鼠标和触屏都仅处理浏览器 `click`，不再同时监听 `touchend`；同一实体索引与同一房间/场次/手/窗口内的两次点击间隔不超过 450ms 才出牌，出牌后 650ms 屏蔽连点。第二次点击后等待 80ms 再复核当前牌、座位和窗口，让排队的尺寸/方向变化能够取消出牌。换房、换手、手牌或窗口变化、屏幕尺寸或方向变化清除待完成的点击；在途请求、非本人回合和非法动作不能出牌，服务端继续复核窗口。
- 选中时仅移动牌面，按钮命中区保留原位，便于在原触点完成第二次触摸。碰、杠、胡、过等动作与园子风险提示保留。

3. `node --test shared/logic/mahjong/*.test.mjs`，以及 `node --test server/mahjong-http.test.mjs server/mahjong-restart.test.mjs server/mahjong-room.test.mjs server/mahjong-store.test.mjs`。
4. `node scripts/test-mahjong-ui.cjs` 保留阶段4的结算、多人胡、房间失效和摊牌回归；`node scripts/test-mahjong-polish.cjs` 覆盖三种横屏、密集牌河、多副露与花、牌墙张数、鼠标及模拟触屏双点、真实本地房间出牌、窗口变化和竖屏往返。两项浏览器测试需要本机 Playwright、Chromium，可通过 `NODE_PATH` 和 `CHROME_PATH` 指定。
