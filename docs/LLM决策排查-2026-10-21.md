# 线上 AI 决策排查与验证（2026-10-21）

排查基线为 `567f5d6c21b8d55f087b175efef551cdee43e6db`。线上全局模型 Key 未配置，数据库聚合确认存在个人 DeepSeek Key；诊断只输出配置是否存在，不输出 Key。原牌局已关闭，旧版本没有保存提示词/响应正文或成功请求记录，无法逐条还原用户刚才那手的模型输入输出。

## 确认的问题

1. `room.hostUid` 在线上房中是服务端生成的座位 ID，个人 Key 查询需要账号绑定的设备 UID。原调度器直接用座位 ID 查 Key，AI 座位自身也没有账号，导致即使房主配置了 Key 且开启大模型，也静默使用本地策略。现通过房主座位的 `accountUid` 查 Key。
2. 本手公开行动在调度器截到最后 20 条、提示词再截到 14 条，河牌时可能丢掉翻前/翻牌/转牌行动；提示词也没有标注行动所属轮次。现保留完整本手公开行动，逐条注明轮次。
3. `amount` 是动作实际支付额，`betTotal` 才是本轮累计下注。原提示词把实际支付额写成“加注到”，且观察对象丢掉了 `betTotal`；加注范围也因未适配引擎的合法动作字段而显示为 0～0。现分别传递和说明两个金额，提供真实合法加注范围，并区分本轮与本手累计投入。
4. 原调度器只在请求前检查手牌/回合。现同一房间只允许一个在途决策，请求前和回复后都检查房间实例、手牌、回合、当前座位及其参局/弃牌/全下/失格状态。换回合、重置、销毁时取消在途请求，迟到回复不能执行或触发本地补动作。

## 河牌“连续加注120”

完整服务端牌局可复现：两名 AI 河牌先下注到60，随后依次加注到120、180、240；后三次各自实际投入都为120。旧界面全部显示“加注120”，累计注额被隐藏。现显示“加注到240（本次投入120）”。

随后另一名 AI 跟注补60，牌局立即摊牌、派彩，行动者及 AI 计时器清空，再触发旧回调也不会请求模型。未复现“最后跟平仍继续决策”的规则故障。原牌局已销毁，无法断言它的实际动作序列；不能将合法的连续加注当成重复跟注，也不额外限制加注次数。

## 调用记录

服务器日志新增三类结构化记录，以房间/手牌/回合/座位关联：

- `[ai] llm_request`：模型、轮次、本手输入历史条数；表示真正进入模型请求。
- `[ai] llm_result`：成功、失败或过期丢弃、解析后的动作及耗时。
- `[ai] decision`：最终采用 `llm` 或 `local`、实际动作、支付额、累计下注、是否执行和回退原因。

不记录 Key、私牌、提示词正文、响应正文或思考理由。请求次数、成功解析次数、最终采用次数分别统计，非法模型动作及缺 Key 的回退可追踪。调用失败继续安全回退，避免牌局卡住。

配置 Key 后仍需在建房时勾选“AI 用大模型决策”并选择对应模型。仅配置 Key 不会自动开启所有房间的大模型模式。
