# 线上入座与异步状态

- 列表和房号入口先调用真实 join，保存该房间座位凭证后再进入房间页。进行中加入的新玩家仍旁观；列表对此显示「旁观」。扫码入口同样先 join 再跳转。
- 座位认证由服务端执行。客户端不得通过伪造 isMe、补造底牌或跳过认证解决旁观问题。
- 每次状态请求捕获发出时的房号、seatId 和 seatToken。响应返回时，只在房间和凭证仍与请求一致的情况下应用。rev 只能表示牌局版本，不能证明响应属于当前座位身份；相同甚至更高 rev 的匿名响应也不能覆盖入座后的身份。
- 轮询与首次 pull 使用同一身份检查规则。入座响应也绑定原房号和凭证，避免切房后写入错误房间。
- 凭证只在内存比较及按房号的本地存储中保留，不写日志。真实无凭证的旁观者仍接收公共局面，没有底牌或行动权限。
- 本地复现与验证：`node --test scripts/test-online-seat-client.mjs`，再运行 `npm run test:online` 和 `npm run build`。前者使用真实账号、HTTP 房间与发牌引擎，通过延迟匿名/旧令牌回包复现入座竞态，不依赖真实模型或生产账号。
