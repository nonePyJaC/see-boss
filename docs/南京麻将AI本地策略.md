# 南京麻将 AI 本地策略

本文件记录阶段 3 已实现的本地策略。它是确定性的启发式策略，不是训练好的麻将模型，也不保证胜率或专业水平；模型决策属于阶段 5。

## 决策边界

- `server/mahjong-room.mjs` 先从当前座位的权限投影构造观察，包含自己的手牌、合法动作和摸牌上下文，以及公开牌、行动、余额、庄家、翻倍、三嘴与园子来源快照。
- 策略不接收完整房间、其他人暗牌、牌墙顺序、尚未裁定的其他人响应、座位凭证或模型密钥。被碰/杠的弃牌按副露计一次；南京麻将暗杠牌值公开，计入四张已见牌。抢补杠时，申请补杠的第四张虽暂留在对方手中，也作为公开牌计入。
- 模型没有参与本阶段。AI 和超时托管通过同一个本地策略选动作，之后仍交给现有牌局引擎复核和推进。策略异常时从合法动作中选择保守回退，不将非法动作交给引擎。

## 计算与选择

1. 计算普通四面子一将的向听距离，并单独计算七对及南京双七对（一个四张加五对）；花杠不占普通面子。`-1` 表示成牌，`0` 表示听牌。
2. 出牌先比较向听，再比较能够降低向听的未见牌张数；同分时参考公开已见牌并使用稳定次序。已见张数来自自己的手牌及公开弃牌、副露和花堆，不把未知牌假定为真实牌墙。
3. 碰牌对比碰后最佳出牌与原局面；杠牌对比杠后补牌前的牌形。部分条件下避免因开门而增加小胡硬花门槛。报听只在规则引擎已给出合法报听动作时选择。
4. 合法胡牌按当前公开余额、当局倍率、三嘴、园子来源和杠开来源估算付款；多人仍可能同时胡时仅是单个胡家的估算，并非最终金额。负收益胡牌与简化的后续损失风险进行比较，选择胡或过；这不是对对手手牌或真实胜率的推断。
5. 唯一合法动作直接采用；超时窗口内各座位分别根据其安全观察决策，不依赖其他人尚未公开的响应。

## 验证和限制

- `node --test server/mahjong-ai.test.mjs`：覆盖牌型向听、有效进张、公开牌计数、碰/杠、园子付款决策、超时托管和隐私隔离；并构造规则引擎认可的成牌检查向听计算。
- 固定随机种子的四策略自对局用于验证合法性、推进和耗时，不是用户实战记录，也不是实力排名。测试仅提供本机性能样本，目标服务器和真实多人环境仍需实测。
- 没有进行基于真实牌谱的训练、对手手牌推断或经过统计验证的胜率评估。后续可在规则不变的前提下用对照局评估和改进策略。
