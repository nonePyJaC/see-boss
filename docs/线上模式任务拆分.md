# 线上模式（多人联机对局）任务拆分

> 本文档是唯一的事实来源。每完成一项，把 `- [ ]` 改成 `- [x]` 并记一行备注。
> 规则：** Phase 7（零留存）不允许延后**，它和功能同批上线。

## 背景结论（已实测，不要再质疑）

- 云函数可用，且以 **admin 身份**读写 CloudBase PostgreSQL（`@cloudbase/node-sdk` + 环境注入的临时密钥）
- 因此 `decks` 表可做成「仅云函数可读写」，前端 anon 角色碰不到 → 发牌防作弊成立
- `shared/logic/*.mjs` 是现成的纯函数牌局引擎（80/80 测试），**直接 import，不重写成 plpgsql**
- 前端 `OnlineRoomView.vue` 当前 0 个 `repo` 调用，全本地状态 → **整体重写**

---

## Phase 1 — 云函数基建

- [ ] `cloud-functions/online/`：单一云函数，内部按 action 分发（`deal`/`act`/`showdown`/`state`）
      - 理由：一个函数比四个函数省冷启动，且共享 `shared/logic` 依赖
- [ ] `cloudbaserc.json`：固定 envId、timeout、memorySize、envVariables
- [ ] `shared/logic` 打包进函数：函数内 `require('../shared/logic/betting.mjs')` 不可行（部署包只含函数目录），需复制或用构建脚本
- [ ] 身份校验封装：从 `event` 里取 CloudBase 注入的 `TCB_UUID` / 匿名身份，映射成 uid
- [ ] 统一返回结构 `{ ok, code, data }`，前端封装成 `onlineRepo`
- [ ] `scripts/deploy-online-fn.sh`（或 .cmd）：一条命令构建+部署
- [ ] **清理探针函数** `pg-probe` / `pg-probe2` / `hello`（`tcb fn delete`）
- [ ] **配 HTTP 访问**：`tcb fn deploy <fn> --httpFn`（或控制台配 HTTP 触发器），
      否则前端只能用 `app.callFunction`，且拿不到调用者身份。
      已验证：`tcb fn invoke` 的 event 为空对象，uid 解析为 ''，**不能用来做身份测试**。
- [ ] `whoami` 探针部署为 HTTP 函数，从前端匿名登录态调用一次，
      确认能拿到真实 uid 后才算 Phase 1 完成。

### 待验证风险
- [ ] 云函数能否可靠拿到调用者 uid（匿名登录用户的 sub）。这是 RLS/归属判定的根。
      必须先用一个 echo 函数验证，再做后续。

---

## Phase 2 — 发牌 `deal`

- [ ] 校验：仅房主可发起；房间 `status='waiting'`；人数 >= 2
- [ ] 洗牌（`cards.mjs` 已有工具）
- [ ] 写 `decks`：整副牌 + 已发位置 + burn 区
- [ ] 写 `hands`：每人 2 张底牌（**只写自己的，读时按 uid 过滤**）
- [ ] 扣盲注：`set_blinds` 已定的小麦/大麦，从 `room_members.seeds` 扣，计入 `bet`
- [ ] 房间 `status='playing'`，记录 `current_turn_uid`、`current_bet`、`min_raise`
- [ ] 全部在单事务内（`app.rdb().transaction()` 或顺序调用+失败回滚）

### 验收
- [ ] 两个身份调 `deal`，各自只能看到自己的 2 张牌
- [ ] 盲注正确扣除，`pot` = 小+大

---

## Phase 3 — 动作 `act`（过牌/跟注/加注/弃牌/全下）

- [ ] 校验轮次：`current_turn_uid === 调用者`，否则拒绝
- [ ] 校验金额：跟注不能超过持有；加注 >= `min_raise`
- [ ] 写入 `room_members.bet` / `total_bet` / `folded` / `all_in`
- [ ] 回合推进逻辑：移植 `betting.mjs` 的 `nextToAct` / 街完结判定
- [ ] 街道推进：`preflop → flop(3张) → turn(1) → river(1) → showdown`
      翻牌时写 `boards` 公共牌（需新增列或复用 `decks`）
- [ ] **幂等**：同一 action 重复提交不重复生效（`version` 字段 or action 序号）

### 待决策
- [ ] 公共牌存哪儿：`decks.burned` 复用 or `rooms` 加 `board jsonb` 列？
      倾向后者，读一次房间就拿全，省往返。

---

## Phase 4 — 摊牌 `showdown`

- [ ] 满足摊牌条件时自动触发（或房主点「开牌」）
- [ ] 比牌力：`hand-evaluator.mjs`
- [ ] 分池：`side-pot.mjs`（all-in 场景）
- [ ] 写回 `room_members.seeds`，更新 `rooms.status`
- [ ] 提前结束：只剩一人未弃牌 → 直接赢池，不摊牌
- [ ] **线上模式不发金瓜子**（`payGoldenSeeds` 保持 no-op，这是法律红线）
- [ ] **不写 history 表**（线上零留存）

---

## Phase 5 — 前端重写 `OnlineRoomView.vue`

- [ ] 删除全部本地 `ref` 状态（`holeCards` 9 处、`seats`、`pot` 等）
- [ ] 新建 `client/src/data/online-repo.js`：封装云函数调用 + 轮询（复用 `realtime.js` 的 poll 机制）
- [ ] 状态模型：单一 `roomState` ref，来源只有云函数返回
- [ ] UI 复用 `OfflineRoomView` 的视觉语言：圆形玩家卡、瓜子图标、公共池
- [ ] 我方的底牌要大（可点选）；他人只见牌背
- [ ] 操作按钮按轮次启用/禁用：过牌/跟注/加注/弃牌
- [ ] 轮询间隔 2s（与线下一致，避开 CDC）
- [ ] 退出房间：调 `leave_online_room`，确保本地状态清空

### 验收（真机）
- [ ] 两手机扫码进同一房间
- [ ] A 看到 2 张底牌，B 看到自己的 2 张，**A 看不到 B 的**
- [ ] A 过牌 → B 屏幕 2s 内变成 B 的回合
- [ ] 打到摊牌，两边看到同一份分配结果

- [ ] 确认 `history` 表在线上路径**零写入**
