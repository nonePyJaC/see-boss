# AI 提示词与输出约定

当前代码提示词版本：`poker-facts-v8`，版本标识写在固定 system 消息内，供私有复盘区分。完整system与匿名示例见[提示词v8](AI提示词v8.md)。

## 输入

- `server/ai/llm.mjs` 组织固定 system 规则和逐次重建的 user 局面。固定前缀不随座位、牌面、阶段或人设变化，缓存命中仍以供应商 usage 为准。
- user 按「规则和盲注 → 本手固定座位表 → 上一手公共短结果 → 完整本手历史 → 当前AI身份/底牌/最新局面 → 自身近8手打法 → 当前辅助风格 → 合法动作」排列。前半段不依赖当前AI视角；相同历史使用同一座号，不替换成「我」。昵称用JSON字符串转义，座号按引擎本手座位顺序分配，同名玩家也有不同编号。
- 追加公开行动时保留已有历史逐字前缀，轮次标签只写短名；实际投入、累计下注、全下标记不省略。历史后面的最新状态仍每次重建，不能复用先前模型的决策或混入其他AI底牌。没有行动记录的首次请求不存在可追加的历史前缀保证。
- 每次请求仍包含完整本手公开行动，保留轮次、本次投入、本轮累计下注及全下标记。不得为减少 token 省略翻牌前或此前轮次，下一手重新开始本手历史。
- 按钮、小盲、大盲身份来自当前手引擎的公开座位字段。原先多人桌即使剩两人，也不改用「按钮就是小盲」的双人桌规则。本轮座次顺序剔除弃牌/全下者，明确它不是「尚未行动者」列表。
- `server/ai/prompt-facts.mjs` 仅接收安全 observation：自己的底牌、公共牌、公开座位/投入及行动。不得增加其他玩家底牌、牌堆、令牌、Key 或完整 Room。
- 程序给出最佳五张、实际牌型和踢脚、与公共牌配成的顶对/次对、一张成顺或成花的未知牌张数。短牌使用36张牌堆和对应牌型规则。
- v8另列公共牌各花色张数，仅计公共牌，不把自己的同花底牌混入；零跟注成本只写“本次跟注成本0”，不暗示免费过牌就是更优动作。
- 有踢脚的牌型另列底牌/公共牌的踢脚来源；口袋对高于所有公共牌时注明超对，新高张出现后不再保留旧超对标签。两对先比较对子等级，不能把共享公共踢脚当成私人优势或主要弱点。
- 底牌结构在翻前和翻后都明确给出：同花/不同花、常规点数差、中间隔张数、连张/非连张。对子不当作连张；长牌A低位、短牌A低位的连接关系另列，不混同于常规高位点数差。
- 动态后段增加分圈行动角色和当前响应摘要：逐圈分别统计主动下注/加注者与跟注者，仅当前圈统计曾过牌者、尚未行动者及最后出价者。待响应名单读取引擎的公开`actedUids`，经安全观察白名单转换为`actedSeatIds`，包括加注后需再次行动的人，并剔除弃牌/全下/无后手者。缺失引擎字段时明确未知，不能将曾行动等同于已经完成响应。
- 角色摘要从完整本手行动重建，放在`【当前决策】`后，不破坏公共历史追加前缀。常用的听牌概率和静态赔率限制集中在固定system规则，动态段保留事实和数值。
- 同一动态区另列「可追加筹码对手」：仅包括非本人、未弃牌、未全下且仍有后手的公开座位，并列出后手。它与待响应名单不同，已过牌/跟注者仍可能支付；状态缺失记未知，不据此断言零人。本人尚欠金额与check合法性另列，付款字段缺失时不宣称免费过牌。
- 同花强度只比较同花的差异高张，不代表绝对坚果。听牌概率只指下一张成顺/成花，不是干净补牌或实际胜率，不能将重叠听牌直接相加。
- 跟注成本按剩余筹码封顶；公开累计投入完整时排除自己无法争夺的超额池，保留弃牌者已经投入的死钱。权益门槛是无后续投入的静态参考；不同边池需分别评估对手，累计投入缺失时明确按全池简化。
- 最低所需权益只是价格参考，不是实际权益或自动跟注依据；需判断能赢对手合理范围的哪部分。公共牌配对、两对或三条时，核对底牌是否改善最佳五张与实际踢脚；没有可信权益或弃牌概率时定性判断。
- 下注尺度使用该动作出手前的底池。加注的实际投入含补跟部分，与加注增量及累计加注到的金额分开说明。
- 只向LLM发送最近一手的一句公共结果，如「座2（两对，摊牌胜1人，分池6850）」；不附上一手牌面、逐街流水或跨手对手统计，房间原有历史留存不变。牌型来自公开摊牌结果；多人分池不写成击败全部对手。未摊牌只写下注/加注后弃牌收池，不猜测高牌或诈唬；分池排除已知未匹配退款，不表述为净利润。资料缺失明确未提供。

## 输出

模型只返回一行 JSON：`action`、仅 raise 时的 `amount`、`reason`、`nextStyle`。

- `action` 必须是当前合法列表中的 `fold`、`check`、`call`、`raise` 或 `allin`。
- `raise.amount` 是整数，表示本轮累计下注到的总额，位于合法范围；首次下注也使用 raise。其余动作不附 amount。
- `reason` 要求一句不超过80字的简短决策依据，引用当前牌力、关键历史或成本，说明取值、半诈唬/诈唬、控池、跟注或弃牌的目的；加注说明尺度依据。
- 引用行动时注明轮次和座号，输出前与程序底牌结构和角色摘要核对；不把对手下注说成跟注，不把上一圈过牌当作当前圈已过牌，不保证尚未发生的“免费到下一圈”。
- 决策优先级：实际牌力与牌面 → 对手公开行动及合理范围 → 价格、位置和有效后手 → 风格参考。风格参数生成方式不改，仅把输入描述改为辅助偏好并放在事实之后；不能仅凭人设决定弃牌、跟注或控池。强牌可以合理慢打，有听牌也可以因价格不合适弃牌，不设固定动作配额。
- 买牌是正常策略：价格合适、听牌质量与权益实现支持时，明确考虑call继续争池；不能只因尚未成牌、非坚果或可能再被下注就弃。翻牌普通跟注按下一张机会考虑后续收费；已经全下且不需再付费才可评估剩余两张机会。转牌一张、河牌不再买牌；结合位置、后手、隐含及反向隐含赔率，不以静态门槛代替实际权益。
- 结合本手人数、位置、尺度、轮次和前序路线分析对手，不把下注等同于必有强牌、过牌等同于弱牌；也不假定对手必有诈唬。顶对好踢脚、超对不因面对下注自动弃牌或自动跟注，必须结合可赢范围和价格判断。
- 价值下注要有可支付的对手和可能跟注的较弱范围；半诈唬/诈唬要有仍能弃牌的对象及合理弃牌机会。中等摊牌价值允许check/call，强牌可造池或有依据地诱导；大注/全压可用于有依据的价值或诈唬，不设统一禁令或固定频率。
- 明确无人可追加筹码、本人不欠注且check合法时，指引选择check；仍欠注则评估call/fold；第三方可支付时仍可争取价值或边池。合法动作列表原样保留，不用提示词替代引擎约束。
- 消费完整历史以延续此前进攻/控池目的，遇危险新牌、较强反击或不合价格允许改线或直接弃牌。首次决策也可零追加筹码fold；不新增持久化计划，不要求长篇思考。
- 慢打/控池给出具体收益或风险，不能只写人设、后手深或对手可能埋伏；河牌没有下一张免费牌，应围绕取值、抓诈或退出解释。已过牌但待再次响应的人不得称为本街未行动。
- 未知对手范围必须作为推测表述，不编造确定底牌或胜率，不输出详细内部推演。
- v8要求每次填写`nextStyle`：`base`（回该座位自己的基础人设）、`balanced`（均衡）、`pressure`（主动）、`patient`（稳健）、`tricky`（有依据的变化）；保持时也填写当前枚举，不强制切换。解析器继续兼容省略或未知值并保持原风格，不增加重试、不把合法动作判废。成功采用模型动作后才更新风格，从下一次请求生效；失败、非法动作回退、过期响应不更新。
- 自身历史仅统计本房间同一AI最近8手已完成牌局的实际公开动作：弃牌手数、连续弃牌、自愿翻前入池手数、下注/加注、跟注、过牌、面对下注及其中弃牌次数。盲注不算自愿入池，全下按实际累计下注归类。当前未完成一手仍看完整本手历史；样本少就如实报告，不把自己的统计当作对手倾向。
- 自身历史作形象/风格参考；不能用“过去常弃”证明当前该弃，不断言对手必然据此调整。check须比较具体范围、风险或诱导收益，不能仅写免费、控池或怕被加注；诱导须保留对手后续行动机会。
- 当前风格和自身历史放在个人动态段，不改变共享缓存前缀或基础人设参数，不进入本地策略或数据库。普通开始下一手会延续；移除AI、解散房间或重置牌桌清空。风格变更只进7天私有复盘的 `output.nextStyle` 与 `execution.styleChange`，不向公开状态或普通日志展示。

动作仍经过服务端合法性校验；格式、网络或动作错误沿用本地策略降级。以上属于输入/输出指引，不保证模型每次都能遵守，后续实战继续用私有日志评估事实错误与决策质量。

## 复盘与验证

真实输入、简短依据、执行结果和 usage 沿用根目录 `AGENTS.md` 的私有7天留存约定，不进入普通日志、HTTP 状态或 Git。

v8验证价格合适时的买牌输入、好价/差价与翻牌/转牌区别、公共花色计数、风格明确选择、私有复盘及完整历史/缓存前缀。线上集成只用模拟模型，无付费调用；没有新增自然语言关键词硬校验或重试。对应命令：

```text
node --test server/ai/prompt-v8.test.mjs server/ai/prompt-facts.test.mjs server/ai/prompt-street.test.mjs server/ai/llm.test.mjs server/ai/llm-cache.test.mjs server/ai/llm-self.test.mjs server/ai/decision-review.test.mjs server/ai/llm-online.test.mjs
```

以下保留为v6历史验证记录（不重新生成已接受的v6示例）：

node --test --test-name-pattern='^C1 |v6 牌力和行动|上一圈过牌不进入' server/ai/prompt-street.test.mjs

新事实字段需验证只使用公开信息和自己的底牌；改动提示词需保留稳定前缀及逐轮完整历史测试。本地策略不读取提示词，本次没有改变它的决策规则。

v8保留模型、温度、token预算、超时、本地回退和原私有记录字段；只重组提示词、明确风格输出要求，并补公共花色计数和中性价格措辞。固定system由v7的2086字符缩至1558字符（减少25.3%，不是供应商token计量）。验证不证明真实模型行为改善或缓存命中提高，后续由自然试玩日志确认。

用户预览见[两手三人桌示例](AI提示词v6两手预览.md)。17次示例使用真实提示词构建器，动作由人工指定、经现有引擎校验；不得将它们称为模型实际输出。v5固定system为2042字符，v6为1912字符；同局面示例总输入减少3.20%，这是字符数，不是供应商token或费用保证。

已知引擎限制仍未修复：唯一对手全下、无人欠注时仍可能继续产生决策机会。提示词选择check不会自动收街或发完公共牌，也不是规则层保证；该问题继续单独保留。
