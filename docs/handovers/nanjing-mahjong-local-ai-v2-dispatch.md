# 南京麻将本地AI多路线与打法差异改动方案

> 日期：2026-10-30  
> 方案版本：nanjing-local-policy-v2  
> 状态：待安排实现、待owner review。本文是开发与验收要求，不代表功能已实现。  
> 工作目录：`D:/newPoker`。先阅读根目录 `AGENTS.md`、[线上规则确认](../../南京麻将线上规则确认.md)和[当前本地策略说明](../南京麻将AI本地策略.md)。用户后续明确修订优先。

## 1. 改动目标

当前本地AI主要按“向听最少 → 有效未见进张最多 → 固定次序”选出牌，已经能完成合法对局，但偏向最快听牌，缺少主动做清一色、混一色等大牌的取舍。同样的观察往往得到同样的动作。

本轮让AI同时比较成牌速度、做牌收益和公开风险，在合理候选之间形成有限的风格与随机差异。允许它有依据地牺牲一点速度做大牌，也能在条件变差时放弃目标。不能只提高花数、只提高胡牌率，或靠随意拆牌制造变化。

用户示例是“10张万子＋二三四条”。新策略应能比较保留顺子快胡与拆条子做清一色两条路线。是否值得拆，取决于万子的具体结构、新摸入的牌、已见牌、剩余牌数、公开威胁和实际可收付；不能把“已有10张同花色”直接写成必拆规则。

## 2. 范围与既有能力

| 本轮实施 | 本轮边界 |
| --- | --- |
| 路线约束下的牌形距离、进张与收益潜力 | 不修改胡型、计分、付款、发牌或其他规则 |
| 出牌及碰杠时的路线取舍和改线 | 不改网页操作，不混入依赖升级或德州策略 |
| 轻量风格、合理候选的带权随机及可复现性 | 不接付费模型，不训练模型，不实现完整对手手牌推断 |
| 简单、可解释的公开风险指标 | 不把启发式分数称为真实胜率或经过验证的EV |
| 对照验证、受控计算开销、合法回退 | 不新增长篇思考输出或长期计划系统 |

继续使用引擎给出的合法动作，以及现有座位认证、响应窗口、超时和快照机制。保留DeepSeek/阶跃星辰及个人Key设施，后续模型阶段仍可复用本地策略作为回退。

本轮的变化主要落在尚未胡牌时的路线选择和碰杠取舍。默认保持现有正收益合法胡的采用逻辑，不通过随机放过已可获得的正收益胡来制造变化；主动拒绝正收益胡追更大牌不在本轮默认开启范围。园子等负收益合法胡继续评估实际收付，由策略选择，不改成非法或强制过。

## 3. 决策顺序

按以下优先级组织：

1. 真实牌局事实、合法动作和已确认规则。
2. 路线是否可达、实际收益潜力、速度成本与公开风险。
3. 本手路线的适度连贯性。
4. 小幅风格偏好和接近候选之间的随机。

实现流程为：安全观察 → 枚举合法候选 → 对各候选评估多条路线 → 综合比较 → 在接近候选中选择 → 最终合法复核与提交。不能先按当前最小向听只留下一个动作，再给它补一个“做大牌”理由。

## 4. 路线评估

### 4.1 首版路线

至少评估普通胡、清一色、混一色、对对胡、七对和双七对；清一色、混一色按目标花色分别评估。无花果、全球独钓、门清及其他加成继续由规则事实与计分函数识别，本轮不要求为每个加成都建立独立计划。

每条路线至少返回：是否仍可达、距离与进张、需放弃的手牌组合、破坏路线的动作、计分及收付假设、速度和风险成本、综合分以及一句简短依据。

路线距离必须符合该路线的约束。例如，不能用普通顺子胡的最小向听冒充清一色距离，也不能把其他花色的改善牌算进清一色有效进张。

区分不可逆事实与可调整手牌：

- 已碰出其他花色的牌，会使相应清一色路线失效；不能继续为该路线加分。
- 暗手中存在其他花色，只表示需要换掉这些牌，不能据此直接判定清一色不可达。
- 普通胡的成牌距离不等于南京麻将的合法起胡资格。非门清小胡不足4硬花时，不能当成已经获得合法听牌或胡牌收益；未来能否补够花不能写成确定事实。
- 七对、双七对不能有手牌碰、直杠、暗杠或补杠。自动花杠仍作为花牌处理，不破坏七对资格。
- 双七对沿用最新修正：14张全成对，含1～3组四张均属于双七对，统一100花替代七对50花，不按四张组数继续加档。
- 地胡报听后的动作限制、过水和过碰仍由引擎执行。不能为了路线目标越过合法动作列表。

### 4.2 速度与进张

对每个合法出牌，比较出牌后各路线的距离，以及能改善该路线的有效未见牌。已见牌包括本人手牌、公开弃牌、各家副露、花和已公开的补杠张；暗杠按四张已见处理，被碰走的弃牌不能重复计数。

未见牌可能在对手手中，不能当成真实牌墙中的剩余张数。目标牌已全部可见时，不能仍以该牌作为有效进张。剩余摸牌机会要随公开剩余牌数变化，不能到牌墙末段仍使用开局时的收益预期。

完整顺子被拆、对子被拆、碰杠毁掉七对等，应有明确成本；这些成本不能成为一律禁止拆牌的硬规则。也不能设置过紧的“只能选择全局最小向听”筛选，使做牌路线永远无法参与比较。

### 4.3 收益潜力与真实付款

计分与收付复用现有 `scoreHand`、`settleOnlineWin` 等纯函数或其安全封装，不另写一套南京计分公式。

已经存在合法胡时，可按当前事实计算该次单胡收付；多人尚未响应时，继续标明这是单个胡家的估算，不能冒称最终已确定金额。

未成牌路线只能提供带明确假设的收益参考：

- 区分可能的点炮、自摸、园子来源及包牌场景，不能默认未来必然自摸、必收三份。
- 考虑对手当前余额、园子、三嘴绑定、当局倍率和余额封顶。高花数若不能带来更多实际可收，额外收益应明显降低。
- 未来付款人、牌型是否最终成立、余额是否变化均未知，不能把静态估算写成保证收入。
- 牌型与加成遵守互斥和叠加；牌型未形成时不预先领取天胡、地胡、花开、杠开等奖励。
- 杠钱和同牌罚单独处理，不能在目标胡款中重算已付费用。对可确定的即时收付应按实际规则评估。

收益、速度和风险应采用可解释的统一尺度，或先归一化再比较。实现者须给出各项单位、方向、权重与阈值，不得直接把“花数100”“向听1”“未知风险0.8”无说明相加。若使用完成难度折扣，必须标注其为启发式，不是实测胜率。

### 4.4 公开风险

首版只使用公开证据，例如对手报听、公开副露、出牌历史、剩余牌数与已见张数。副露多不等于一定听牌，同色副露不等于已经清一色，未知情况保留不确定性。

南京当前规则没有日麻的振听规则，不能机械套用“对手打过这张，所以绝对不会胡”的安全牌结论。风险指标可以影响候选排序，但不能编造对手暗牌、精确听口或放炮百分比。

风险惩罚也要有上限和依据，避免所有AI因缺乏信息而普遍转为保守。当前有明确进攻收益且风险可接受时，应允许继续做牌。

## 5. 连贯与改线

每手可以有一个当前倾向路线，用小幅连贯性奖励减少相近评分之间的反复横跳。路线不是不可撤销承诺，不能因为上一轮选过清一色就持续丢掉更好的机会。

出现以下事实时必须重新评估：目标牌大量已见、关键进张耗尽、路线因副露失效、剩余机会不足、普通胡出现明显更好的机会、公开威胁明显增加，或园子/责任/余额变化改变收益。

改线允许转向快胡，也允许原本普通胡在新牌改善后转向大牌。路线切换阈值及奖励需集中配置，不能散落为某张牌、某个昵称或某次实战的专用补丁。

若需要记忆，只保存路线ID、少量决策指标、风格与随机种子等必要字段。通过现有快照机制恢复；新手重置路线，新场按既有规则重新初始化。策略内部路线不得进入普通HTTP状态或其他玩家观察，也不新增长篇持久化计划。

## 6. 风格与合理随机

首版可使用“均衡、偏速度、偏做牌”三种轻微偏好；风险取舍主要随当前局面变化，不把某一风格固定成永远防守或永远追大牌。每位AI在一场内保持基本偏好，避免每个动作重新随机性格。

先过滤不合法、不可达及明显较差候选，再从评分足够接近的候选中带权选择。清楚占优的动作应能跨风格稳定采用；只有确实接近时才允许风格和随机改变结果。不能用统一随机弃牌率、固定追清一色次数，或“最近没做大牌所以现在必须做”制造变数。

随机源可注入。固定策略版本、风格、种子及相同观察必须得到可复现结果；同一窗口重复求值、重试或恢复不能重新抽签来试探动作。同一个种子不能跨房间共享可变游标而相互影响。换手、换场和过期窗口的处理继续遵守现有边界。

## 7. 工程接入与性能

主要入口为：

- `server/mahjong-ai.mjs`：当前向听、进张、出牌与碰杠决策。
- `server/mahjong-room.mjs`：安全观察、超时托管及快照适配。
- `server/index.js`：AI调度与最终动作提交。
- `shared/logic/mahjong/hand.mjs`、`score.mjs`、`online-payments.mjs`：权威规则与计分复用。

可按职责拆分路线评估、候选评分、风格与随机模块。保留当前v1为可调用的基线和异常回退，实施前固定基线提交及测试种子；不要让所谓基线在对照中也悄悄调用v2逻辑。

出牌、碰、直杠、暗杠和补杠应使用一致的路线评估。不能出牌时在追双七对，碰杠判断却只看普通向听，随即把路线无依据破坏；也不能为保路线把本来合法的碰杠从动作列表删掉。

首轮不做全量对手暗牌枚举或无界搜索。计算循环应有可生效的预算检查及缓存上限；策略预算到达后回退v1或已有最佳合法候选。不能仅在同步计算全部结束后看耗时，再把这称为超时保护。

建议将单次策略计算的初始硬预算设为500ms，并报告同机平均、P95、P99与最大耗时，结合既有响应期限和目标服务器实际情况复核。这个值是实现目标，尚无新版本实测结论。策略处理后仍需核对原场次、手号和窗口；计算完毕不代表旧动作仍可提交。预算不足不能阻断其他真人请求或让多个AI排队后天然超时。

## 8. 可解释性与复盘

测试诊断至少包含策略版本、观察标识、当前风格、被比较的路线、候选动作、各项分数、选择/改线原因和是否回退，足以判断本次是在追收益、保速度还是降低风险。

说明必须对应真实计算项，不能只在现有最快胡动作后面附加一段“为了清一色”的文案。输出短结构与一句依据即可，不生成完整思考正文。

生产记录沿用 `AGENTS.md` 的私有路径、权限、保留7个UTC日期和容量限制；复用现有记录设施，必要扩展仅限有助于复盘的短字段。输入、候选、理由、本人私牌、种子等策略内部信息不得进入HTTP、普通日志或对手观察。用户实战导出仍放在已忽略目录，不入Git。合成测试样本和生产实战记录必须分开标明。

## 9. 构造验收例

下列是待实现时补齐的合成场景，不是用户实战复盘，也不表示仅凭一句概况就能确定唯一正确动作。实现者须提供完整合法手牌（含新摸第14张）、副露、花、公开已见牌、余额、责任、剩余牌数及合法动作，并解释预期。

| 编号 | 场景 | 验收重点 |
| --- | --- | --- |
| A01 | 10张万＋234条，早期，万子结构与未见进张良好 | 两条路线均参与比较；至少存在有完整收益依据的样例，使偏做牌策略愿意拆条子，而非始终被最小向听筛掉 |
| A02 | 相近手牌，但目标万子关键张已大量公开、牌墙接近耗尽 | 清一色价值下降，可以主动改线；不能只因同花色数量高而继续追 |
| A03 | 保留234条可形成宽听，追清一色代价明显更高 | 清楚更好的快胡路线不被风格或随机推翻 |
| A04 | 七对、含1/2/3组四张的双七对，与碰杠同时可选 | 正确识别100花口径与碰杠损失；不把暗杠仍门清误认为还能七对 |
| A05 | 已副露的其他花色使目标清一色不可能 | 对应路线失效，不能继续加收益分；可转其他仍成立的路线 |
| A06 | 同样高花目标，对照付款人足额和余额封顶/园子/三嘴场景 | 对实际收付敏感，不能只按牌型花数或必收三份排序 |
| A07 | 对手报听、公开副露增多，但暗牌未知 | 使用公开风险，避免编造听口；对手曾打过的牌不被宣称绝对安全 |
| A08 | 园子点炮或抢园子补杠带来负收益合法胡 | 保留合法胡与过的选择，估算方向正确；不以“收益负”当非法动作 |
| A09 | 候选评分接近，对照不同风格/种子 | 能出现合理差异；相同输入及种子可重现，明显较差动作不进入随机池 |
| A10 | 原路线条件变差，后续又出现明显改善的新牌 | 能解释改线原因；不会每回合无依据横跳，也不会固守已失效目标 |
| A11 | 只有一项合法动作、策略异常、预算耗尽、迟到动作 | 合法推进或安全回退，旧窗口不能再次落动作 |
| A12 | 更换隐藏对手手牌、反转真实牌墙，但本人的安全观察不变 | 决策和路线分数不变；证明没有依赖不应知道的信息 |

## 10. 对照指标与通过条件

先运行构造例及必要单测，再做固定种子的小批离线对照。首轮建议12组初始牌墙，轮换四个座位，让v2与同版本v1基线对战；记录具体局数、座位分配、种子、耗时及策略配置。使用相同初始牌墙不意味着不同策略后续还会摸到相同的牌，不能强行按旧行动结果喂牌。

至少报告：

- 每手实际瓜子变化、按座位拆分的结果，以及点炮/自摸、园子/包牌等原因。
- 胡牌率、胡牌花数和实际净收益的区别，放炮损失、流局比例及完成对局的推进情况。
- 大牌路线选择/放弃/完成的次数，清一色等最终成牌分布；主动追牌后失败的样本也要保留。
- 不同风格的动作与路线差异，随机是否仅出现在接近候选。
- 非法动作、过期提交、回退比例及决策平均/P95/P99/最大耗时。

规则正确、权限隔离、金额和牌张守恒、重复提交保护属于硬要求。不能只以胡牌率更高或牌型更大判通过，也不能以“更有变化”为由掩盖明显的收益退化或普遍过度保守。小批对照用于发现问题和展示取舍，不足以宣称统计显著胜率提升；如结果不清楚，提交证据给owner评估，后续再安排更大样本。

## 11. 实施顺序与交付

1. 固定v1基线，列出首版指标与参数，补齐A01～A12的完整合成输入及预期。
2. 实现路线距离、进张和可解释评分，先在固定风格、无随机情况下验证选择与改线。
3. 接入一致的碰杠判断、轻量风格和可注入随机，验证重试/恢复与性能回退。
4. 运行相关规则、AI与房间回归，完成小批对照，更新当前策略说明，明确哪些已实现、哪些仍是假设。
5. 提交SHA、改动文件、策略版本、参数说明、构造样例选择前后对比、对照结果和已知局限，交owner review。只暂存本任务文件，不含实战数据或密钥；不自行发布。

本轮仅交付该改动文档。后续实现遵守以上范围，目标是让AI有依据地选择更高收益的路线，并能在局面变化时调整，而非保证每次都快胡或每次都做大牌。
