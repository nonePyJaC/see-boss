# 南京麻将本地 AI v2：实现与合成对照

状态：**待 owner review；收益验收尚未通过，不发布**。本文及配套 JSON 全部来自合成牌局，不是用户实战，也没有调用付费模型。固定的 v1 基线提交为 `c6f842b2b97e82997bcb4e27518a6782d92ca317`；`server/mahjong-ai-v1.mjs` 是该提交策略的独立副本。

## 范围与参数

- 对每个引擎合法动作比较普通胡、三门清一色、三门混一色、对对胡、七对、双七对；碰后模拟可能打出的一张，杠后纳入即时杠款及余额变化。已碰、手牌杠使七对失效；花杠不影响七对。合法正收益胡沿用 v1 的优先逻辑，园子负收益胡仍依实际付款估算。
- 路线距离按面子/对子、可用花色等约束计算；排除已见牌后的有效进张逐张计算。实际听张才调用计分函数验证起胡资格。其他路线使用一副符合现有副露和花牌的示立牌型，通过 `scoreHand` 和 `settleOnlineWin` 计算静态付款参考；无法生成示例时保守不计收益，不等于路线不可达。该示例不是对手暗牌、实际牌墙或未来所得的预测。
- 启发式总分单位是**相对排序点**，不是概率或真实 EV：距离每增加 1 扣 7；有效未见张数最多 30 张、每张加 0.35；静态收付参考先乘墙余折扣 `max(0.08, min(1, wallCount/65))`、距离折扣 `1/(1+0.55×距离)`，再乘 0.42。七对进展系数为 `min(1,max(0.15,(现有对数−2)×0.2))`；双七对再按最多相同张数为 1/2/3/4 张分别乘 0.15/0.35/0.7/1；拆顺子/对子最多扣 3；即时杠款最多按 30 的 0.15 计入；公开风险最多扣 12。点炮/自摸参考权重分别为 70%/30%，仅是场景权重，不是统计概率。实际付款使用当前余额、园子、责任和倍率，假设这些事实未来不变。
- 公开风险中，对手每家报听记 3、每副手牌副露记 0.7（每家副露最多按两副），再按墙余和可见张数作有限缩放；曾打过的牌不视作绝对安全。相近路线最多加 1.5 连贯分，差距超过 3 不加；三种稳定风格的路线偏移为 ±0.7。仅在距离最高分不超过 2.5 的合法候选中按 `exp((分数−最高分)/2)` 带权选择；随机由策略版本、场次、手、窗口、座位和种子稳定决定。路线按手保存到私有快照，风格由场次与座位稳定派生。
- 同步计算每轮检查 500ms 预算，缓存最多 2 万条；服务端最多两个独立工作线程，700ms 未返回或并发繁忙时使用快速合法回退，线程内预算耗尽先尝试独立 v1。快速紧急回退优先合法胡/报听/过/出牌，不等价于 v1。回调重新检查原场、手、窗口、截止时间和托管身份。私有复盘沿用原有文件目录、权限、轮换与保留策略，记录真实观察、短诊断、动作和实际执行状态，不放入 HTTP 状态。

路线距离和完成折扣仍是启发式：常规面子距离对未知剩余组合做乐观估计，完整性由当前有效张和成牌规则再检查；不包含完整的剩余牌组合可达性证明。未来可能付款人、余额和花牌变化均未知；园子、包牌等假设不能视作保证收入。实际环境下还未验证 worker 启动开销和并发上限是否适合服务器负载。

以上对照显示 v2 在这个小样本净收益和胡牌比例均落后，且没有完成追求中的大胡：**不能声称策略实力提升，也不能把本轮判作收益验收通过**。样本小、同一组牌墙有相关性、参数曾根据前期小样本调整，结果不具有统计显著性；建议 owner 先审查路线权重及碰杠取舍，再用独立种子、更多牌墙复测。

本机热缓存同步对照：460 次 v2 决策平均 125.2ms、P95 241.0ms、P99 282.6ms、最大 377.7ms；0 次预算回退、0 次非法输出，牌局均结束且余额守恒。同步脚本中的过期数为 0 不等于异步竞态已覆盖；另有独立过期窗口、重连和私有状态回归。性能会随机器、缓存和并发变化。

本机 24 次新建 worker 的冷启动测试见[冷启动明细](nanjing-mahjong-local-ai-v2-synthetic-cold.json)：平均 317.6ms、P95 474.5ms、P99/最大 499.7ms，0 次非法输出、0 次回退。24 次不足以覆盖高负载或长尾，尚无 ECS 实测，不能据此保证服务器总耗时低于 500ms。500ms 是线程内策略目标，700ms 是包括启动和通信的外部终止界限。
